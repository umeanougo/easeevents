Executive Summary

Shopify is built for one merchant. Moventory operates across many.

The core issue is not fulfillment execution itself. It is fragmented operational visibility across storefronts. Moventory acts as a centralized fulfillment partner for multiple brands, but each Shopify store still behaves like a separate operational silo.

Current bottleneck

The team manually checks individual Shopify stores throughout the day to catch new orders, returns, delivery needs, and fulfillment exceptions. This works at a small scale, but it becomes increasingly fragile as more brands join.

Recommended move

Build a lean operational visibility MVP before investing in heavy platform infrastructure. The MVP should validate workflow behavior, reduce daily context switching, and establish the technical foundation for future orchestration.

Current State
Operating Problem

Manual store-checking is becoming the scalability bottleneck.

What happens today

  • Each Shopify store is checked separately multiple times per day.
  • Warehouse checks and Shopify checks are split across different places.
  • New orders, returns, and delivery issues require manual attention.
  • Moventory must remember which stores have and have not been checked.

Why it breaks as volume grows

  • A next-day order can be missed until it is already late.
  • Inventory counts can drift between Shopify and the physical warehouse.
  • Shopify notifications route to the merchant, not necessarily Moventory.
  • Moving from 8 Shopify brands toward 14+ makes the current approach untenable.
Strategic Principle

Phase 1 should not attempt to replicate Shopify Admin. The highest-leverage move is to create an operational queue that shows what Moventory needs to act on across stores.

Risk Operational impact Phase 1 response
Missed new orders Late fulfillment, especially for next-day shipping. Unified queue sorted by newest order first.
Store-switching fatigue Manual checks compound as new brands onboard. One dashboard across initial Shopify stores.
Inventory uncertainty Physical warehouse and store data can diverge. Foundation for inventory verification workflows.
Notification gaps Shopify alerts are not optimized for Moventory's multi-brand role. Future notification and exception layer.

Phase 1 MVP
Proposed Build

Operational Visibility MVP: one queue for multi-store Shopify orders.

Phase 1 goal

Eliminate the need to manually log into multiple Shopify stores throughout the day just to know whether there are orders requiring attention.

  • Consolidated order dashboard
  • 3-5 Shopify integrations initially
  • Centralized operational queue
  • Customer and fulfillment visibility
  • Store/client source column
  • Basic filtering and search
  • Operational status foundation
  • Deployment and documentation

Recommended stack

  • Python + Streamlit
  • Shopify GraphQL Admin API
  • Render or Streamlit Cloud hosting
  • Lightweight architecture that can graduate into a fuller platform

Estimated hosting: CAD $10-$30/month depending on usage.
